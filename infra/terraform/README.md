# AWS infrastructure

Terraform for deploying the Student Feedback Portal to AWS. **None of this is required to run the
project** — `docker compose up` from the repository root is the supported path. This exists because
"it runs on my laptop" and "it runs in a VPC with private subnets and rotated secrets" are different
claims, and the second one should be reviewable.

## What it provisions

```
Internet
   │
   ▼
┌─────────────────────────────────────────────────────────────┐
│ VPC 10.20.0.0/16                                            │
│                                                             │
│  public subnets (2 AZ)          private subnets (2 AZ)      │
│  ┌──────────────┐               ┌────────────────────────┐  │
│  │ ALB :80/:443 │──────────────▶│ ECS Fargate · backend  │  │
│  │ NAT gateway  │               │   ↓                    │  │
│  └──────────────┘               │ ECS Fargate · analytics│  │
│                                 │   ↓                    │  │
│                                 │ RDS MySQL 8.4          │  │
│                                 └────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
        S3 (attachments)   Secrets Manager   ECR   CloudWatch
```

| File | Contents |
|---|---|
| `network.tf` | VPC, subnets, IGW, NAT, route tables, four security groups |
| `database.tf` | RDS MySQL 8.4, parameter group, generated credentials, Secrets Manager |
| `storage.tf` | S3 attachment bucket, two ECR repositories with lifecycle policies |
| `iam.tf` | Task execution and task roles, least-privilege S3 and secrets policies |
| `compute.tf` | ALB, target group, ECS cluster, task definitions, services, autoscaling |
| `outputs.tf` | URLs, endpoints and repository URIs |

## Security posture

- **Nothing application-related is in a public subnet.** Only the ALB and the NAT gateway are.
- **No credential is written down.** The database password, JWT signing key and analytics API key
  are generated by `random_password`, stored in Secrets Manager, and injected as container
  `secrets`. They never appear in source, in a task definition, or in the console.
- **Two IAM roles per task.** The execution role pulls images and reads secrets *before* the
  container starts; the task role is what the running application gets. The backend's task role
  can do object operations on one bucket, and nothing else.
- **Tiered security groups.** The ALB accepts the internet; the backend accepts only the ALB; the
  analytics service accepts only the backend; RDS accepts only the backend.
- **Encryption at rest** on RDS (`storage_encrypted`) and S3 (SSE-S3), with public access blocked
  and versioning on.
- **Port 80 only redirects.** The HTTPS listener is commented out because it needs an ACM
  certificate for a domain you own — uncomment it and supply `certificate_arn` once you have one.

## Using it

```bash
cd infra/terraform
cp terraform.tfvars.example terraform.tfvars   # gitignored
$EDITOR terraform.tfvars

terraform init
terraform plan
terraform apply
```

Then build and push images to the ECR repositories the outputs name:

```bash
ECR=$(terraform output -raw backend_ecr_repository)
aws ecr get-login-password --region ap-south-1 | docker login --username AWS --password-stdin "${ECR%%/*}"

docker build -t "$ECR:v2.0.0" ../../backend && docker push "$ECR:v2.0.0"
aws ecs update-service --cluster "$(terraform output -raw ecs_cluster_name)" \
                       --service sfp-prod-backend --force-new-deployment
```

## Cost

Rough monthly estimate in `ap-south-1` at the defaults, outside the Free Tier:

| | |
|---|---|
| ALB | ~$18 |
| NAT gateway | ~$32 |
| Fargate (2 × 1 vCPU backend, 1 × 0.5 vCPU analytics) | ~$60 |
| RDS `db.t4g.micro`, 20 GB gp3 | ~$15 |
| S3, ECR, CloudWatch, Secrets Manager | ~$5 |
| **Total** | **~$130/month** |

`terraform destroy` when you are done. `deletion_protection` and `skip_final_snapshot` are keyed on
`var.environment`, so a `dev` stack tears down cleanly while a `prod` one refuses to.

## Known gaps

Honest about what this does not do, because a reviewer will notice:

- **Remote state is commented out.** Uncomment the S3 backend and point it at a bucket you own
  before more than one person touches this.
- **One NAT gateway, not one per AZ.** A deliberate cost trade; it is a single point of failure for
  egress.
- **No WAF and no CloudFront.** Both are reasonable next steps for anything public-facing.
- **No blue/green deployment.** ECS rolling updates with a deployment circuit breaker and automatic
  rollback, which is adequate here but is not zero-risk.
